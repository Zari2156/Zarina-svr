# Ads Control — сервис аналитики Facebook Ads + amoCRM

Сервис сам забирает данные из Facebook Ads и amoCRM, объединяет их по объявлению
(ad_id), считает CPL, ROAS, конверсию лид→оплата и выдаёт дэшборд с
рекомендациями в стиле "маркетинг-ассистента": что масштабировать, что отключить,
где дорогой лид.

**В интерфейсе есть выбор даты/периода** (вверху дэшборда) — как в самом Facebook
Ads Manager и amoCRM: выбираете диапазон дат, нажимаете "Показать" — видите данные
именно за этот период. Facebook отдаёт данные с разбивкой по дням, amoCRM —
сделки, созданные в этом диапазоне.

## Архитектура

```
Facebook Marketing API ─┐
                         ├─► sync.js ─► SQLite (data.sqlite) ─► /api/dashboard ─► дэшборд (public/)
amoCRM API ──────────────┘
```

- `server.js` — Express-сервер, отдаёт API и статику дэшборда
- `src/facebookClient.js` — забирает данные по объявлениям из Facebook Insights API
- `src/amoClient.js` — забирает сделки из amoCRM с кастомными полями атрибуции
- `src/sync.js` — джойнит оба источника по `ad_id`, считает метрики
- `src/recommendations.js` — правила рекомендаций (легко редактируются)
- `src/db.js` — хранилище (SQLite-файл, ничего дополнительно ставить не нужно)
- `public/` — сам дэшборд (HTML/CSS/JS)

## Что нужно получить перед запуском

### 1. Facebook
1. Business Manager → Настройки бизнеса → Пользователи → Системные пользователи → создать
2. Выдать системному пользователю доступ к рекламному кабинету
3. Сгенерировать токен с правом `ads_read` — он не протухает, в отличие от личного токена
4. Взять ID рекламного кабинета (в Ads Manager, вид `act_XXXXXXXXXX`)

### 2. amoCRM
1. Настройки аккаунта → Интеграции → Создать интеграцию → Частная интеграция
2. Сгенерировать **долгоживущий токен** (не требует обновления, в отличие от обычного OAuth-токена)
3. Понадобится поддомен (`yourcompany` из `yourcompany.amocrm.ru`)
4. ID полей custom_fields, куда Zapier пишет `campaign_id`/`adset_id`/`ad_id`, и ID воронки/статусов —
   их не нужно искать руками: после того как впишете токен и поддомен в `.env`,
   запустите сервис и откройте `http://localhost:3000/api/amo-meta` — увидите все поля и воронки с их ID в JSON.

## Запуск локально

```bash
npm install
cp .env.example .env
# впишите токены и ID в .env
npm start
```

Откройте `http://localhost:3000` — там кнопка "Обновить данные", которая запускает
первую синхронизацию.

## Развёртывание, чтобы был доступен по ссылке

Это обычное Node.js-приложение, разворачивается на любом хостинге с поддержкой Node:

- **Render.com** или **Railway.app** — самый быстрый способ: подключаете GitHub-репозиторий,
  указываете переменные окружения из `.env` в панели хостинга, готово. Бесплатного тарифа
  обычно достаточно для внутреннего инструмента.
- **Свой VPS** — `npm install && npm start` за `pm2` или как systemd-сервис.

SQLite-файл (`data.sqlite`) — это и есть база данных, отдельно PostgreSQL/MySQL поднимать не нужно.
Только убедитесь, что на хостинге диск персистентный (Render/Railway — да; часть serverless-платформ — нет).

## Автосинхронизация

По умолчанию (`RUN_CRON=true` в `.env`) сервис сам обновляет данные каждый день в 6:00
(настраивается через `CRON_SCHEDULE`, синтаксис как в обычном cron).
Кнопка "Обновить данные" в интерфейсе всегда доступна для ручного запуска.

## Как настроить логику рекомендаций под себя

Всё в `src/recommendations.js` — простые, читаемые правила, не "чёрный ящик":
- 0 лидов при ненулевом расходе → критично, проверить объявление
- лидов много, продаж 0 → кандидат на отключение (порог — `REC_MIN_LEADS_FOR_DISABLE` в `.env`)
- CPL выше среднего по аккаунту в 1.5+ раза → предупреждение "дорогой лид"
- ROAS выше порога (`REC_MIN_ROAS_FOR_SCALE`, по умолчанию 3x) → рекомендация масштабировать
- высокая конверсия лид→оплата → отметка "сильный оффер"

Пороги меняются в `.env` без правки кода. Если позже захотите более сложную логику
(например, ML-модель, а не пороги) — этот модуль легко заменить, не трогая остальной сервис.
